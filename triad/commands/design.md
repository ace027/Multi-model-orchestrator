Design workflow. Arguments: $ARGUMENTS

Load the tools: ToolSearch with query `select:mcp__triad__domain,mcp__triad__persona_run,mcp__triad__planning_status`. Detection, teams, wave patterns, document scaffolds, lifecycle status, completion checks and grades are in code (domain tool). Design documents are supplementary: never block a phase on them.

**system** (default) — design brief and design system document.
1. Call domain action `detect` (with the current phase). If the phase is not a design phase, say so and ask whether to continue anyway.
2. Brief questions (AskUserQuestion; skip what the phase or CONTEXT.md already answers): Q1 focus (Design system / Component library; UX research / User testing; Brand refresh / Visual identity; UI implementation / Screen design). Q2 only for a design system: scope (Foundation only (tokens + guidelines); Foundation + Core components; Full system). Q3 existing brand guidelines (Yes, established brand; New brand / No guidelines; Partial / Needs refresh). Q4 platforms, multi-select (Web (responsive); Mobile (iOS/Android); Desktop application; Design documentation only). Q5 accessibility (WCAG AA; WCAG AAA; Basic compliance).
3. Consultation (skip when Q1 is UI implementation): ask the aesthetic direction (3-5 of Brutally Minimal, Refined / Luxury, Playful / Friendly, Editorial / Content-First, Data-Dense / Dashboard, Bold / Expressive, each with its risk level). Then for typography, color, layout and motion offer a SAFE CHOICE and a CREATIVE RISK (what you gain, what you risk, why it fits). Fonts: prefer Satoshi, General Sans, Instrument Serif, Fraunces (display), DM Sans, Geist, Outfit, Plus Jakarta Sans (body), JetBrains Mono, Geist Mono (mono); avoid Inter, Roboto, Open Sans, Lato, Montserrat, Poppins; never Papyrus, Comic Sans, Impact, Copperplate, Brush Script. Reject the AI-slop patterns: purple-to-blue gradient backgrounds, 3-column icon-in-circle feature grids, centered-everything layouts, uniform border-radius, decorative gradient blobs, generic stock hero, emoji as design elements, alternating left-right sections, gradient buttons as the only CTA, colored left-border accent cards. Warn (never block) on incoherent combinations.
4. Call domain action `team` (domain design, answers: disciplines, brand, platforms, backend, visual, polish, feedback) and show it.
5. Call domain action `write` (kind system, the project name, fields: scope, platforms, accessibility, principles, any token and component rows agreed). Then persona_run `design-ui-designer` (read_only false, writable = that path, label `design-system`) to fill the principles, the three-tier tokens (global → semantic → component, `{category}-{modifier}` naming, all eight categories: color, typography, spacing, elevation, border-radius, animation, breakpoint, z-index) and the atoms and molecules (states default/hover/active/focus/disabled/loading/error, variants, accessibility, responsive, dark mode). Call domain action `check` on it and fix what it reports once.
6. Report the path, the team, and how plans use it: `/triad:plan` references it in each plan's context.

**research** — call `write` with kind research and the research name; persona_run `design-ux-researcher` (writable = that path) to fill goals, methodology (from User Interviews, Usability Testing, Competitive Analysis, Card Sorting, Heuristic Evaluation, Survey, Analytics Review, A/B Testing), findings (`### Finding N: {title}` with Observation, Impact, Evidence, Severity), personas, journey map, recommendations, next steps. Move status with domain action `status` (Planning → In Progress → Complete) and run `check`.

**review** — three-lens review of a built design phase, in parallel with persona_run (read_only): `design-brand-guardian` (brand: palette matches tokens, type scale, logo clear space and minimum size, imagery, UI copy voice, pattern consistency), `design-ux-architect` (accessibility: contrast AA 4.5:1 text and 3:1 UI or AAA 7:1, keyboard, visible focus and tab order, ARIA, touch targets 44x44 mobile / 24x24 web, reflow, prefers-reduced-motion, 200% text), `design-ux-researcher` (usability: Nielsen's 10). Findings as BLOCKER (brand violation, accessibility failure, usability critical), WARNING or INFO with file:line. Append the three verdicts to the phase review file; BLOCKERs go to `/triad:review` fixes.

**audit** — post-build audit, only when the phase is a design phase, a design document exists, the phase has summaries and settings `review.evaluator_depth` is `multi-pass`. persona_run `design-ui-designer` (categories: visual hierarchy, typography, color and contrast, spacing and layout, motion, content and microcopy, AI slop) and `design-ux-architect` (interaction states, responsive, performance: LCP < 2.5s, CLS < 0.1) with HIGH (usability/accessibility), MEDIUM (visual), LOW (polish) findings. Call domain action `grade` with the HIGH and MEDIUM counts and the slop pattern count; append the grades and findings to the review file. HIGH findings go to the fix cycle; MEDIUM are reported; LOW are logged.
