<task type="auto">
  <name>Task 1: Search-based AI</name>
  <files>js/ai.js</files>
  <action>
Rewrite chooseMove with two modes. (1) Connected mode, when the two heads share a free component: depth-limited alpha-beta over the simultaneous-move game modelled as me-move then opponent-move per ply (cells the opponent can also enter this tick are treated as dangerous: a mutual move into the same cell is a draw, scored as worse than any safe alternative but better than a sure loss), with iterative deepening bounded by a fixed node budget (no clock), move ordering from the previous iteration, and a Voronoi evaluation (BFS from both heads over free cells: cells strictly closer to me minus strictly closer to the opponent, with a small bonus for my reachable component size and a penalty for articulation-point / dead-end entries). (2) Separated mode, when the heads are in different components: maximise own survival length with a space-filling search (flood-fill area minus wasted cells, e.g. a checkerboard-parity bound and chamber/articulation-point counting, with a few plies of lookahead within a node budget). Hard rules in both modes: never return the reverse of me.dir; never return an immediately fatal move (out of bounds or blocked) when a non-fatal one exists; if none exists return me.dir. Purity: no Date/performance/Math.random, no module-level mutable state (preallocated typed arrays inside the call only, or module-level constants), do not mutate view or view.grid. Work only from view, so it is symmetric for P1 and P2.
